### [谷歌移除 Chrome 商店中的 MV2 扩展，uBlock Origin 受影响](https://webiterate.dev/google-removed-extensions-ublock-origin-108/) ⭐️ 7.0/10

谷歌已将包括 uBlock Origin 在内的 Manifest V2 扩展从 Chrome 网上应用店移除，标志着 Chrome 扩展生态向 Manifest V3 过渡的关键一步。这一变更影响大量仍依赖 MV2 的扩展开发者与广告拦截用户，MV3 对扩展 API 的限制可能削弱广告拦截能力。社区反响强烈，不少用户建议转向 Firefox 以保留完整的 uBlock Origin 功能。

hackernews · twapi · 8月31日 21:10 · [社区讨论](https://news.ycombinator.com/item?id=49514878)

**「背景」** Chrome 扩展长期使用 Manifest V2（MV2）规范，广告拦截工具如 uBlock Origin 依赖其强大的 webRequest API 来在网页加载前阻塞请求。Google 为提升扩展安全性、性能与隐私保护，主导向 Manifest V3（MV3）迁移，但 MV3 改用限制更多的 declarativeNetRequest API，弱化了传统拦截能力，因此 uBlock Origin 等扩展无法在新规范下保持原有功能。Google 已于 2024 年开始逐步停止支持 MV2 扩展，并在 Chrome Web Store 下架这些扩展，同时向用户显示警告。

**「影响」** Chrome 用户将无法再从官方商店安装或更新 uBlock Origin 等 MV2 扩展，现有已安装的 MV2 扩展也可能在后续版本中停止工作。对于依赖广告过滤保障上网安全的普通用户，这一变化可能增加他们遭遇恶意广告的风险。

**「社区讨论」** 评论中多数用户对谷歌此举表示不满，认为广告拦截已成为安全需求；不少人分享了自己迁移到 Firefox 的经验，并指出 uBlock Origin 在 Firefox 上表现最佳。

### [Wrapture：面向测试与追踪的 Python 新库](https://simonwillison.net/2026/Aug/31/introducing-wrapture/) ⭐️ 7.0/10

Graham Dumpleton（wrapt、mod\_wsgi 和 New Relic Python agent 的作者）发布了 Wrapture，这是一个基于 wrapt 的 monkeypatching 思想、同时面向测试与追踪的 Python 库。它能够包裹任意函数或方法，记录所有访问，或覆盖其返回值，因此既可作为 unittest.mock 的替代方案，也可用于为现有项目添加追踪。Wrapture 提供 OpenTelemetry 支持，并包含完全基于配置的追踪接入机制（如 TOML 配置 capture、observe 和 sink）。该项目只有几周大，仍是早期阶段，但 Graham 表示其每一行代码和文档均由 AI 助手在他指导下编写，并强调这不是盲目 vibe coding，而是经过精心设计的工程。后续文章还展示了通过 binding 实现 stub 返回值以及调用后转换返回值等测试模式。

rss · Simon Willison · 8月31日 23:59

**「背景」** wrapt 是 Python 中用于函数与方法装饰和 monkeypatching 的库，而 unittest.mock 是标准库中常用的 mock 工具。Wrapture 将 wrapt 的包装机制扩展到测试场景，让开发者可以在不修改被测代码的前提下观察或覆盖调用结果。

**「影响」** 对于使用 Python 进行测试和可观测性开发的团队，Wrapture 提供了一种统一、声明式的方式来模拟调用和采集追踪信息，可能减少对 unittest.mock 的依赖并简化 OpenTelemetry 集成。

### [滑窗注意力优于线性注意力](https://www.reddit.com/r/MachineLearning/comments/1w3j1vw/slidingwindow_attention_beats_linear_on/) ⭐️ 7.0/10

一篇新 arXiv 预印本声称，带 sink 的滑窗注意力（SWA）在长上下文推理基准上的表现比线性注意力变体高 2 到 10 倍，具体任务包括 Needle-in-a-Haystack 和 BABILong。作者 Alexia Jolicoeur-Martineau、Rhea Sanjay Sukthanker、Pashmina Cameron 和 Emy Gervais 认为，线性注意力研究并未与更简单的基线进行充分比较，并强烈建议改用无需后训练、速度快且内存占用低的 SWA。预印本也承认，线性注意力可能仍需从头训练或大量后训练才能赶上 SWA。因此，这一结论挑战了当前投入后训练算力以生产线性注意力模型的趋势，但其作为单个预印本的影响还有待验证。

reddit · r/MachineLearning · /u/Justgototheeffinmoon · 8月31日 16:35

**「背景」** 标准 Transformer 的注意力机制随上下文长度呈二次方增长，线性注意力等改进试图降低这一成本，但常常需要为模型做专门的后训练或从头训练。滑窗注意力则限制每个位置只关注附近窗口内的 token，并加入 sink token 保留全局信息，是一种简单、无需额外后训练就能控制计算和内存开销的既有方案。

**「影响」** 若该预印本的结果能被复现，正在投入大量资源做后训练以构建线性注意力模型的团队应把 SWA 作为最关键的对照基线，否则可能高估线性方案的收益。

### [GNN 在动态图上可能只是会时间泄漏的 MLP](https://www.reddit.com/r/MachineLearning/comments/1w3imxy/your_gnn_is_probably_just_an_overcomplicated_mlp/) ⭐️ 7.0/10

Reddit 用户 Glabmayt2075 指出，在动态图上用静态快照训练 GNN 会导致时间泄漏：标准 2 跳消息传递会把未来边引入当前损失，模型在训练时就能看到未来。为强制因果边界，他们发布了 SynthFin-AML v10.0（10 万节点、120 万边），采用 Day 7/8/10 三个时间快照物理分离训练、验证和测试图，并把欺诈与正常交易金额设为同一对数正态分布以消除表格泄漏。在严格时间切分下，LightGBM 使用 11 个点时间图特征的 PR-AUC 为 0.848，归纳式 GraphSAGE 为 0.881，说明 GNN 优势真实但不大。该基准已以 PyTorch Geometric PR \#10774 提交上游，希望成为动态图评估的更严格标准。

reddit · r/MachineLearning · /u/Glabmayt2075 · 8月31日 16:21

**「背景」** 图神经网络（GNN）通过消息传递聚合邻域信息；在反洗钱（AML）交易网络中，若直接将整张动态图做成静态快照并随机划分训练/测试，GNN 的 k 跳感受野会跨越时间，把未来交易边当作邻居特征参与训练。SynthFin-AML 是为此发布的合成金融交易数据集，用严格按时间截止的快照划分来避免这种泄漏，并让欺诈与正常交易金额分布完全相同，防止模型仅凭金额大小区分类别。

**「影响」** 对使用动态图做金融反洗钱或时序图评估的开发者来说，这一工作提示标准随机划分会高估模型性能；SynthFin-AML 和 PyG PR 提供了一种可复现的因果分割基准。由于帖子未经同行评审，实际适用性还需后续验证。
